## Stale File Handling Policy

1. **Content-Hashed Filenames**: Vite assigns a unique hash to every asset based on its content (e.g., `index-CnhuM1d3.js`, `index-BqsalW5r.css`).
2. **Entrypoint References**: The live `index.html` references only the exact active bundle entrypoints. When `index.html` is replaced on the server, all subsequent user requests fetch exclusively the new chunk hashes.
3. **Orphaned / Stale Files**: When rebuilding without cleaning `assets/`, old hashed files from previous builds remain on disk. They do not conflict with new builds because filenames differ. However, to prevent disk bloating:
   - Deployments should synchronize with deletion: `rsync -avz --delete dist/ user@server:public_html/` or delete the target `assets/` directory before unpacking new build artifacts.
   - If cPanel File Manager is used, remove outdated `.js` and `.css` files that no longer match the active manifest.
